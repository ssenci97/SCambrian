## 1. Data summary

### 1.1 Purpose

The project compares the proteomes of four *Aedes* species in protein language model embedding space. It identifies protein groups whose share differs between species and groups that are conserved. It reuses public data only and generates no experimental data.

### 1.2 Input data

| Label | Species | Source | Identifiers | Content |
|---|---|---|---|---|
| `koreicus` | *Ae. koreicus* | Curated proteome from [kor_it / kor_hu / both] | see below | Protein FASTA |
| `japonicus` | *Ae. japonicus* | Curated proteome from jap_it | see below | Protein FASTA |
| `aegypti` | *Ae. aegypti* | UniProtKB | query `(organism_id:7159)`, release [UniProt release] | Protein FASTA and annotation TSV |

|---|---|---|

### 1.4 Volume

- Raw inputs: a few GB.
- Model weights: about 27 GB. They are cached, not redistributed.
- Embeddings: about 4 KB (300M), 4.5 KB (600M) and 10 KB (6B) per protein.
- Total derived data: below 50 GB.

### 1.5 Sensitive data

None. All data are public and come from non-human organisms.

## 2. FAIR data management

### 2.1 Findable

- Source data have persistent identifiers (section 1.2).
- Derived data will be deposited on Zenodo with a DOI: [dataset DOI].
- Both repositories will be released through GitHub–Zenodo with a DOI: [code DOI].
- Files are prefixed with the label. Output names carry their parameters.
- Joint clusters are named with letters, per-species clusters with numbers.
- Metadata:
  - curated FASTA headers carry provenance (section 2.3);
  - `CITATION.bib` and `ACKNOWLEDGEMENTS.txt` list sources and licences;
  - `.h5ad` files store their parameters in `uns["params"]`;
  - dedup outputs have a `.params` file.
- Each published result reports the repository commits, model versions, software versions, UniProt release and download date ([download date]).

### 2.2 Accessible

- Source data are open on NCBI, Zenodo and UniProt. No login is needed.
- ESMC weights are public. No token is needed.
  - 300M and 600M are downloaded by `ESMC.from_pretrained()`.
  - 6B is downloaded by `huggingface_hub.snapshot_download()` and mapped onto the `esm` model by `src/extract_reps_biohub.py`.
  - Inference runs locally. The hosted API (biohub.ai, formerly Forge) is not used.
- Derived data will be open on Zenodo at publication.
- Code is public on GitHub under [code licence].
- Download scripts:
  - mosquito data: `slurm_dw_proc.sh` (HTTPS, Zenodo API);
  - UniProtKB: `slurms/01_dw_uniprot.sh` (UniProt REST `stream` endpoint).

### 2.3 Interoperable

- Formats are open: FASTA, GFF3, TSV/CSV, NPZ, H5AD, YAML, PNG/PDF/HTML.
- FASTA headers:
  - Italy: `>id=<seqid> organism=<species> dataset=<IT_GKMD01|IT_GKMC01> type=<ORF type> len=<aa> strand=<+|-> pos=<start-end> score=<score>`
  - Hungary: `>id=<seqid> organism=Aedes_koreicus dataset=HU_GCA_024533555.2`
- UniProtKB accessions and NCBI Taxonomy IDs (7159, 7160, 140438) are kept as provided.
- Curation:
  - TransDecoder (`--single_best_only`) predicts ORFs from transcripts;
  - gffread extracts proteins from the genome annotation;
  - SCambrian uses the [filtered (complete ORFs only) / unfiltered] proteomes.
- The proteomes differ in origin (predicted ORFs, gene models, UniProtKB entries). Two steps limit the bias: deduplication at 95% identity, and normalisation of cluster counts by proteome size.
- Software: Python 3.10, PyTorch 2.4.1 (CUDA 12.1), flash-attn 2.6.3, `esm` [esm version], Scanpy ≥ 1.10, igraph, umap-learn, scikit-learn, hdbscan, MMseqs2 [MMseqs2 version], TransDecoder [version], gffread [version]. The environment is built by `esmc_config.sh`.

- Earlier ESMC releases had other licences: Cambrian Open (300M), Cambrian Non-Commercial (600M), Cambrian Inference Clickthrough (6B, Forge/AWS only). The licence valid at download applies. The download date and snapshot hash are recorded.

Quality assurance:
- Downloads are checked (gzip/FASTA signature, no HTML error pages), written atomically and retried.
- FASTA headers are validated. Sequence and error counts are logged.
- Missing inputs or invalid paths stop a step with an error. Dependent steps are cancelled.
- The 6B checkpoint load fails on any missing or unexpected parameter.
- Cluster metrics are reviewed before interpretation.

Reproducibility:
- Parameters are in `configs/param_configs.yaml`. Labels and queries are in `configs/query_configs.tsv`.
- Scripts read and write their parameters with `--yaml-in` and `--yaml-out`.
- Steps rebuild only missing or outdated outputs.
- The random seed is 42.
- Slurm logs record job ID, date, run time and memory.

Availability: Zenodo keeps deposits for the lifetime of the repository (at least 20 years).

## 3. Workflow

| Step | Script | Tool and settings | Slurm resources | Output |
|---|---|---|---|---|
| 0. Environment | `esmc_config.sh` | conda | DGX, 1 A100, 16 GB, 4 h | `./.env` |
| 1. Mosquito download | `slurm_dw_proc.sh` (curation) | HTTPS, Zenodo API | 1 CPU, 4 GB, 2 h | `raw/` |
| 2. Curation | `slurm_transdecoder.sh` (curation) | TransDecoder, gffread | 2 CPU, 16 GB, 8 h | `proteomes/` |
| 3. Sequences | `slurms/01_dw_uniprot.sh` | UniProt REST, or copy of local FASTA | THIN, 1 CPU, 2 GB, 2 h | `data/sequences/`, `data/features/` |
| 4. Clustering | `slurms/02_mmseqs2.sh` | MMseqs2: dedup at 0.95 identity, then clusters at 0.9 → 0.2; coverage 0.8 | THIN, 16 CPU, 20 GB, 4 h | `data/dedup/`, `data/clusters/` |
| 5. Embeddings | `slurms/03_reps.sh` | ESMC 300M, 600M, 6B; mean over residues | DGX, 1 A100, 100 GB, 4 h per label × model | `data/esm-reps/` |
| 6. Embedding clusters | `slurms/supp_01_scanpy.sh` | L2 norm, cosine kNN (k = 15), Leiden (res. 1.0), UMAP, t-SNE | EPYC, 16 CPU, 32 GB, 8 h | `.h5ad` |
| 7. Report | `slurms/supp_02_scanpy_report.sh` | Chi-square with BH (q < 0.05), fold change ≥ 2, HDBSCAN viewer | EPYC, 4 CPU, 16 GB, 1 h | PDF, CSV, PNG, HTML |

`bash slurms/run_all.sh` chains steps 3–7.

## 5. Storage and preservation

- **Storage:** ORFEO CephFS. Access is limited to project members.
- **Git:** embeddings, logs, temporary files and the conda environment are not tracked.
- **Raw data:** read-only after download. No script modifies it.
- **Preserved:** code, configuration, credit files, curated proteomes, downloaded UniProt files, clusters, embeddings, `.h5ad` files and result tables.
- **Not preserved:** raw downloads, intermediates and model weights. They can be regenerated.
- **Backup:** Git and GitHub for code. Data are copied to [backup system] every [backup frequency].
- **Integrity:** SHA-256 checksums are stored in `checksums.txt` and deposited with the data.
- **Cleaning:** temporary files are deleted after outputs are validated. Outputs made with outdated parameters are deleted by hand.
- **Long term:** Zenodo.

## 6. Ethics and legal compliance

- The data are public, non-human and non-personal. No ethics approval, consent or GDPR measure is needed.
- Licences are respected as described in section 2.4.
- ESMC is used to describe existing proteomes only. No sequences are designed. This complies with the Biohub Acceptable Use Policy.
